# 唤醒词表（`keywords.txt`）为什么长得这么"裸"

**这个文件里不能有任何注释、空行以外的内容。** 原因是个很有欺骗性的坑：

## `#` 不是注释符，是阈值标记

Sherpa-ONNX 的关键词行格式是：

```
关键词发音单元...  @显示名  :加权  #阈值
n ǐ h ǎo j ūn g ē @你好军哥
```

`#` 后面跟的**阈值**。所以你在文件里写一行注释：

```
# Sammy 的唤醒词表
```

它会被当成一个关键词行去解析 —— 里面那串英文会被拿去转数字，于是报：

```
ValueError: stof: no conversion
```

这个错和真正的原因（"我把注释写进了关键词表"）八竿子打不着，
我第一次就卡在这儿，还把显示名的空格当成嫌疑人查了一轮。

## 显示名里也不要空格

`@嗨 Sammy` 会被空格拆成两个字段 —— 同样报 `stof: no conversion`。
要写 `@嗨Sammy`。

## 为什么同一个词写这么多行

"嗨 Sammy" 是拼音 + 英文混着念的，不同写法/不同人的发音落点不一样。
**多写几行容错**比把阈值调低安全得多 —— 阈值调低会让厨房里的锅碗声也叫醒它。

Rowan 原本想要 "hi Sammy" 但担心英文识别不准，所以中英文两种写法都收，
中文写法放前面（这个模型是中文 WenetSpeech 训的，中文更稳）。

## 怎么改

- 加词：直接往 `keywords.txt` 里加行，格式照抄上面的。
- 改灵敏度：优先加写法，而不是降 `keywords_threshold`（见 `src/sammy/wake.py`）。
- 改完必须实测（`tests/test_wake_live.py` 或 `./run.sh --wake-test`）：
  写法错了**不会报错，只会永远不触发** —— 安静地什么都不做是最难查的失败方式。
