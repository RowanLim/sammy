## 一、界面审美 6 点（原 TUNING §7–11）· 2026-10-14 定

| # | 事项 | 决定 | 为什么不选另一头 |
|---|---|---|---|
| 1 | 字体大小 | **统一 24（像素网格 12 的 2 倍）** | 已经过前后对比 + 3 倍放大验证：24 是唯一不糊又够大的档；恢复层次感可以以后按"角色"给两档，但那要先有真机观感再说 |
| 2 | 打字机节奏 | **保持现值**（`typewriter.py` 的常量） | 现值是照着"能读完又不拖"调的，且已有素材；改节奏是纯审美偏好，没有证据说现值不好 |
| 3 | 思考指示（动点） | **保持现值** | 同上 |
| 4 | 凝视活跃度 | **保持现值** | 已有判据钉死"看得到在动、又不抽搐"；没收到"太活/太死"的反馈就不动 |
| 5 | 好奇淡化时长 | **保持现值** | 淡化是防"啪地换脸"，时间常数已在合理区间 |
| 6 | CRT 强度 | **保持现值（可 `SAMMY_CRT=off` 关）** | 扫描线/辉光/暗角是"老机器"观感的主要来源；强度是可一行调的常量，真机上看腻了再调 |

没有证据的改动就是拿审美赌稳定性 —— 所以一律**定稿为现值**。真机上你要是哪条看不顺眼，说一句我改一个数，五分钟的事。

## 二、《表情总表 v1》§11 七项（硬件侧）· 2026-10-14 定

| # | 事项 | 决定 | 理由 |
|---|---|---|---|
| 1 | 首发表情组 | **12 情绪 + 5 系统态 = 17 个**（推荐原案）<br>情绪：Normal / Happy / Glee / Sad / Angry / Surprised / Sleepy / Squint / Worried / Annoyed / Skeptic / Focused<br>第二批 6 个：Furious / Frustrated / Unimpressed / Suspicious / Scared / Awe | 12 个覆盖"日常可辨"的全谱系（正面 3、负面 5、中性 4）；第二批全是"强烈/复合"情绪，**没有真机动画前设计它们等于空想** |
| 2 | 强情绪升不升 P1 | **不升，维持 P2 轮盘赌** | P1 是"系统事件"（唤醒/睡眠/低电/断连）。**情绪该从它自己的内在状态长出来**，不该被系统事件直接点名 —— 否则"有脾气"就变成"有剧本" |
| 3 | 左右不对称眼型（7 组） | **保留** | 这是"活物感"最便宜也最有效的一招（人眼对对称破缺极敏感）；代价只是两组参数分别调 |
| 4 | 42 个屏幕动画 | **先上 8 个**：thinking / battery / alarm / wifi / wait / ok / heart / love | 覆盖"正在做事/电量/提醒/连接/等待/成功/情感"六个必要场景；其余 34 个是装饰，等真机玩腻了再挑。<br>⚠️ 全部要按 Sammy 的屏尺寸**重绘**（参考是 64×64） |
| 5 | 睡眠阈值与唤醒 | 阈值 **120 秒**（无交互）+ **夜间 23:00–07:00 加速**（与桌面版 `drives.py` 的作息同一套口径）；唤醒 = **唤醒词 + 定时** | 120s 是"你走开一会儿它才睡"的尺度；夜间加速已有桌面版实测（×1.6 消耗）。手势唤醒**暂不列入**（取决于第 7 条） |
| 6 | 点头/摇头幅度 | **按 Sammy 自己的舵机重定，不沿用参考参数** | 参考的参数量纲是它自己的舵机（角度/步延/扭矩都不同）；沿用等于刻舟求剑。数值**等硬件到位后实测标定**，先空着 |
| 7 | 手势传感器（PAJ7620） | **v1 不装；预留安装位与接口** | 没有真机就没有传感器调试条件；但"挥手互动"是这套表情设计的重要输入源 —— 所以**留位留线**，等你真要组装时再决定买不买（花钱的事最后过你一眼） |

**给 Nex 的一句话**：1/3/4/5 是照它的推荐原案定的；2/6/7 是我改的（理由见上表），请按这个更新硬件侧口径。

## 四、省 token（Rowan 2026-10-14：「你自己想办法 节约一些 token 吧」）

**成本结构**（实测一个块 $0.146）：输出 $0.082（**57%**，其中 75% 是思考 ✗）· 缓存命中输入 $0.042（29%）· 未命中输入 $0.022（15%）。
→ 刀口在**思考 token**。

**已做的四刀**：
1. **自主任务关思考**：`hermes cron edit --reasoning-effort none` 给 `sammy-autopilot-offpeak` 与 `sammy-daily-report`；
   `sammy-license-review` 保留 `low`（许可证结论要细）。**交互会话：max → medium**（Rowan 2026-10-14 拍板：「好似 max 和 medium 区别不大」）。
   配置链实测：**任务级 > 按模型覆盖 > 全局 `agent.reasoning_effort`**（`hermes_constants.py:1127` 确实读它；
   `hermes config set` 报"not a recognized key"只是 schema 不全，不影响生效）。
   为什么是"关"不是"低"：DeepSeek 的思考接口只有开关（`thinking: {type: disabled}`），档位参数大概率被忽略 —— 实测 key 401 拿不到真实数据，
   但正因为不确定，才选**唯一确定生效**的那档；预算闸门兜底，质量真掉了改回一条命令的事。
2. **子任务（delegation）从 max 降到 low**（机械活不需要深想）。
3. **每日预算 $1.50 → $1.00**（≈ 7~10 个块；到顶当天停手）。
4. **日志归档**（上一提交）：DEVLOG 235KB→53KB、B2 日志 31KB→18KB —— 压每次调用的上下文底噪。

**怎么验证有没有效**：看 `state.db` 的 `session_model_usage.reasoning_tokens`（每块一条）——
关思考后应显著下降；哪天成本没降或质量掉了，改回 `--reasoning-effort low` 即可（一条命令）。
