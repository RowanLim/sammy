## 2026-10-01 · M1 骨架

### 1. QImage 的 constBits() 是个会失效的视图（严重）

**症状**：35 张表情里只有一部分渲染正常，其他碎成几块；算出来的外框全都诡异地从 (0,0) 开始；裁切后像素数从 433 掉到 156。

**根因**：`_gray()` 里 `convertToFormat()` 造出的 QImage 是局部变量，函数一返回就被回收。但我把 `constBits()` 的 memoryview 返回出去了 —— 它指向的是那块已释放的内存。随后在循环里连续调用 35 次，每次新的 QImage 分配**复用了刚释放的同一块内存**，于是"读表情 A"实际上读到了表情 B 的数据。

**教训**：**任何返回给外部的 Qt 内存视图，必须立刻 `bytes()` 复制一份。** 别信"memoryview 会保持对象存活"。

顺带把裁切逻辑也改稳了：不再假设"外框一定包住内容"，改成遍历整张源图、只按偏移平移。

### 2. Python 里 `"我在这儿呢".isalpha()` 是 True

**症状**：模型偶尔不按格式输出时，一整句中文正文被当成"情绪标签"吃掉了，用户看到的是 `……`。

**根因**：判断"这个短词是不是情绪标签"时我用了 `word.isalpha()` —— CJK 字符在 Python 里也算字母。于是一个纯中文句子被判成"它想给个情绪，只是词不在表里"，然后整句被丢弃。

**教训**：**处理非 ASCII 文本时，`isalpha()` / `isalnum()` / `isdigit()` 都必须再加 `isascii()` 限定。**

### 3. 这个模型默认会「先想再答」

**实测**：同一个问题，思考链开着 5.28s，关掉 1.95s。看用量是 `reasoning_tokens: 182` 对 `completion_tokens: 193` —— 也就是 94% 的 token 花在"想"上，真正说出来的只有 11 个 token。

**处置**：桌面陪伴场景要的是**快**，所以默认发 `thinking: {"type": "disabled"}`。需要它认真想的时候用 `SAMMY_THINKING=on` 开回来。**这个开关不该写死在代码里抽烟，该由场景决定。**

### 4. 表情取景：并集外框 vs 各自外框

**症状**：第一版用 35 张表情的**并集外框**做统一裁切（本意是让脸不忽大忽小），结果每张脸都被挤在角落、显得很小。

**处置**：改用**固定画框 + 每张脸按自身外框居中** —— 所有表情共用一个画框（最大的那张脸 + 留白），脸的大小稳定，位置也稳定。

**教训**："统一"和"填满"经常冲突，要找一个两者的折中（固定画框尺寸 + 各自居中），而不是二选一。

### 5. 固定字号会切掉长回复

**症状**：回复超过一行时，右边被硬切掉（"养足精神再" 后面没了）。

**处置**：用 `QFontMetrics.boundingRect()` 在 [26, 24, 22, 20, 18] 里挑第一个能装下的字号 —— **宁可字小，也不许丢字**。

## 2026-10-01 · 记忆（槽位 + 日记 + 夜间整理）

**设计**：学 Miru —— `slots` 存结构化事实（昵称/偏好/项目），`journal` 存带日期的事件，`digest` 存每日摘要。三张表分开。

**为什么这么分**：事实要**被改写**（偏好会变），事件**只能追加**（历史不能改）。混在一张表里，早晚会为了改一条事实而破坏历史。

**两个工程决定**
1. **抽取走后台线程，不插进对话延迟** —— 用户看到回复之后才抽记忆，他不用等。
2. **显式要求（"帮我记住X"）先原样存一条高优先级**，不赌模型抽不抽得出来。模型可能会漏，但用户明确说的事绝不能丢。

**踩的坑**：`consolidate_now()` 默认整理"昨天"，自检里当天刚写的记录全被跳过，摘要为空。语义上默认昨天是对的（模拟"睡了一觉"），但**调用方必须显式传日期**，不能靠默认值 —— 这类"合理的默认值"最容易在测试里骗过自己。

**记忆库的备份**：它是 Sammy 的"人生"，丢了不可再生。用 **SQLite 官方 backup API** 取一致性快照 —— 直接拷文件在写入时会拷到半个事务。

## 2026-10-01 · 工程地基（ruff + pytest + pre-commit）

**为什么先做这个**：地基不牢，功能写得越快越贵。原来只有一个手写自检脚本、没有自动检查、代码只在一块外置盘上。

**pytest 当天就抓到 3 个真 bug —— 都不是"写错一行"，而是设计层面的漏洞：**

1. **延迟断言用单次采样 = 假验收。**
   实测同一个问题服务端波动 1.35s ~ 3.09s，写 `latency < 3.0` 的断言会随机挂。
   随机挂的测试比没有测试更糟 —— 人会开始忽略它。
   → 改成测分布（p90 进预算，单次不超 5s）；根治尾延迟靠流式输出，不是靠调参。

2. **记忆写入失败会把回复覆盖掉。**
   `_call_brain` 里一个 try 同时兜住了「对话」和「抽记忆」，记忆一炸就 emit `failed`，
   用户明明已经看到答案，屏幕却跳成"我卡住了"。
   → 两件事分开兜：**回复和记忆的失败不能互相牵连。**

3. **`needs_nightly()` 会重复整理当天。**
   原逻辑是"今天有记录、今天没摘要 → 整理今天"，于是当天一旦整理过，
   之后新增的记录**永远轮不到整理**（有摘要了就返回 None）。
   → 改成：优先补"已经过完但还没整理"的日子（最老优先，能补课）；今天的只在 23 点后才顺手理。

**另外：`SammyWindow` 加了依赖注入**（`brain` / `memory` / `autoconnect`）。
可测试性不是测试的事，是**设计**的事 —— 不能注入，就永远只能靠手动点。

**ruff 的一条配置坑**：中文项目必须关掉 `RUF001/002/003`（全角标点的 "ambiguous unicode"），
否则一个中文代码库会凭空多出 300+ 条纯噪音 —— 规则要按项目调，不能照搬英文项目的默认值。

## 2026-10-01 · 远程仓库 + 凭证审计（教训最贵的一段）

**基础设施**：Nex 那台用 Docker 起了内网 Gitea 1.27.3（`http://192.168.110.177:3000`，SSH 2222），仓库 `rowan/sammy`。
主仓库在外置盘、远程在 Nex、每日快照在内置盘 —— **三重保障，任何一份都能独立恢复**。

配合 Nex 干活时它有两条规矩值得记下来：给它的命令里**只要出现内网明文 IP，它的安全审批就会拦**；
它会**停下来报告而不是绕过去**。第一次卡在 `ROOT_URL`，第二次卡在凭证文件里的展示用网址 ——
两次的处理都不是"换种写法骗过扫描器"，而是**发现那行配置本来就多余，删掉**。

### 凭证审计：三个坑，全靠"反向验证"才挖出来

**核心教训：安全检查必须有反向验证。**
拿一个**故意埋了假凭证的临时仓库**去测它会不会报警 —— 只会说"通过"的检查等于没有检查。
我的审计脚本第一版写了 4 个错：

1. **`grep .env` 会把 `.env.example` 也匹配进去。** 一个正则里的 `.` 匹配任意字符，
   于是空模板被当成泄漏文件报警。**假警报会训练人忽略警报**，比没有检查更危险。
   → 改成按文件名**精确匹配**（`grep -x` / 字符串集合比较）。

2. **`git grep -E` 是 POSIX ERE，不支持 `\b` 词边界。** 写了 `\b` 的规则**静默失效** ——
   检查每次都说"通过"，其实一个字节都没查。这是最危险的一种坏法：**它给你安全感，但不给保护**。
   → 正则一律不用 `\b`/`\s`，改用 POSIX 的 `[[:space:]]`。

3. **别匹配"任何地方的 UUID"。** 第三方 README 里的图片资源 URL
   （`user-attachments/assets/<uuid>`）会成片误报。
   → 改成匹配**凭证赋值语句**的上下文（`key[:=] "<uuid>"`），同时把 vendored 文档显式排除。

4. **`git grep` 默认区分大小写。** 我埋的雷写的是 `API_KEY = "..."`，
   小写的正则 `api[_-]?key` 直接漏过 —— **连自己埋的雷都查不出来**。
   → 加 `-i`，关键词里补上裸的 `key`。

现在这套审计挂在 **pre-push**（全历史扫描）+ **pre-commit**（暂存区扫描）两道。
