## 一、最值得学的三个

### 1️⃣ 小智 `78/xiaozhi-esp32`（30,332★）—— 这个领域的事实标准

中文圈最大的开源 AI 硬件项目，自我定位就一句：*"An MCP-based chatbot"*。配套后端 `xinnan-tech/xiaozhi-esp32-server` 10,716★。

它的后端功能清单基本就是这个领域的**标准件名录**：

| 模块 | 做法 |
|:---|:---|
| 语音交互 | **流式** ASR + **VAD** + 流式 TTS，多语言 |
| 声纹识别 | 识别说话人身份，传给 LLM 做个性化回应 |
| 意图识别 | 外挂意图识别 + **大模型自主函数调用**，插件化处理 |
| **工具调用** | 客户端 IOT 协议 / **MCP**（客户端、服务端、接入点三种）/ 自定义函数 |
| 记忆 | 四档可选：`mem_local_short`（本地总结，免费）/ `mem0ai`（1000 次/月）/ `PowerMem`（OceanBase 开源，智能检索）/ 无记忆 |
| 知识库 | RAGFlow，让模型自己判断要不要查 |
| 工程 | 插件系统 + 热加载；MQTT+UDP 网关 / WebSocket / HTTP；Web 管理台 |

> **👉 该学的：不要自己发明工具层协议，直接上 MCP。** 这是整个生态的共识。

### 2️⃣ `huangjunsen0406/py-xiaozhi`（3,487★）—— 同语言，架构可以直接抄

Python + asyncio，是我们的技术栈里最接近的参考。

- **事件驱动**：asyncio 事件循环，支持高并发
- **分层设计**：应用层 / 协议层 / UI 层 清晰分离
- **依赖注入**：组件生命周期由 bootstrap 容器管理
- **插件系统**：音频、UI、MCP 工具都以插件形式加载
- 音频：Opus 编解码 + 实时重采样
- **语音识别：Sherpa-ONNX 离线模型 + 唤醒词**
- 通信：WebSocket / MQTT 双协议 + 加密 + 自动重连
- 配置：分层 + 点号访问（`a.b.c`）+ 动态更新

> **👉 该学的：分层 + 插件 + 依赖注入；唤醒词/ASR 改用 Sherpa-ONNX（比我们原计划的 vosk 新）。**

### 3️⃣ `kiyotakali/Miru`（167★）—— 形态最像我们，记忆设计最成熟

架构图几乎是我们的目标形态：

```
Live2D 桌宠 + 屏幕感知 + 轻壳  ──>  Flask 后端
                                     · chat agent（读记忆）
                                     · AttentionEngine（决定要不要开口）★
                                     · 记忆系统（槽位 slots + 日记 journal）★
                                     · sleep agent（夜里整理记忆）★
                                     · SSE 多端同步
```

- **三档模型全部 OpenAI 兼容**：`Vision`（读屏幕）/ `Chat`（对话）/ `Memory`（整理记忆）——**用便宜模型干记忆整理的活**，聊天才用好模型
- **本地优先**，没有中心服务（和我们的"独立大脑"决定一致）

> **👉 该学的：`AttentionEngine`（决定要不要开口）和「记忆 = 槽位 + 日记 + 夜里整理」。**
> 后者和 Sammy「会犯困、会睡觉」的产品设定天然契合 —— **它睡着的时候，正好在整理记忆。**

## 二、我们的 PRD 漏了两块

对照 `DasterProkio/awesome-ai-companion`（828★）的分类法，我们在两块上是空白：

### 🕐 漏掉一：Background Heartbeats & Proactive Messaging（主动找用户）

> 这个类别的定义：*让陪伴者在后台保持清醒、接收消息、感知时间流逝，并且**先开口**。*

我们的 PRD 只有 P1-2「每 40 分钟提醒休息」—— 那是个硬编码定时器，不是这个。成熟做法是独立的**注意力引擎**：

| 项目 | 做法 |
|:---|:---|
| `astrbot_plugin_proactive_chat` | 上下文感知 + 持久状态 + **动态心情** + **免打扰时段** + TTS + 独立 WebUI |
| `astrbot_plugin_private_companion` | 连续人格状态 + **日程表** + 重要日期 + 日记 + 低频主动消息（60+ 功能） |
| `laude-institute/headlong` | 持久代理 + **内在独白循环**，保持连续的思维流并主动接触 |

**关键设计点**：主动开口要**有分寸** —— 免打扰时段、频率上限、看上下文决定说不说。做不好就从"陪伴"变成"骚扰"。

### ❤️ 漏掉二：Affect & Drives（驱力系统）

> 这一类别的定义：跟踪 疲劳 / 思念 / 焦虑 / 玩心 / 亲密感 等驱力，随时间与交互漂移，受睡眠周期影响，可落盘。

| 项目 | 做法 |
|:---|:---|
| `chuli1122/Eventide` | 生理状态引擎：身体周期 + **7 条驱力** + 18 个短期事件 + 梦境联动 + JSON 写回 |
| `A1batr055/Drivesoid` | HTTP sidecar 跟踪 疲劳/思念/焦虑/玩心/保护欲/亲密 |
| `Vael-KY/Tidefall` | 六阶段周期 + 7 个漂移值 + pg_cron 自动化 + 浏览器仪表盘 |

> ⚠️ **注意**：你**旧版 SammyDesktop 其实已经有雏形了** —— 状态条（心情 / 饱腹 / 精力）+ 精力低了自动睡觉。**我在新设计里把它丢了，应该捡回来**，而且这是"陪伴感"最便宜的来源：不用花钱、不用调模型，只要让状态随时间漂移、并且**让用户看得见**。

## 五、建议的落地改动（按性价比排序）

### 立刻（改文档，不写代码）
1. **PRD 补两块需求**：主动心跳（含免打扰）+ 驱力系统（把旧版的状态条捡回来）
2. **工具层定 MCP**，不自研协议 —— 于是"解决问题的能力"不用自己从零攒，能直接接生态

### M1 收尾
3. **记忆按「槽位 + 日记 + 夜间整理」设计**：`slots` 存结构化事实（昵称/偏好/重要日期），`journal` 存带日期的事件，Sammy 睡着时（每天凌晨）跑一次整理与摘要
4. **配置分层**：YAML 支持点号访问 + 运行时更新（现在是硬编码常量）
5. **代码组织改分层 + 插件**：音频 / 界面 / 工具各自独立，别都堆在 `pet.py`

### M2（语音）
6. 唤醒词 / ASR 换 **Sherpa-ONNX**（替掉 vosk 计划）
7. 语音链路按 **VAD + 流式** 做，别做成"按一下说一句"

### M4（实体化）
8. 参考 `stackchan-mcp` —— **把 Sammy 的身体（舵机/屏幕/表情）也暴露成 MCP 工具**，这样"脸"和"能力"同一套接口，二期接硬件就是接一个工具
