## 二、分项结论

1. **「学思路、自己设计参数」不侵权。**
   版权保护的是**具体表达**（代码文本、图形素材），不保护**思想、机制、参数取值范围**。
   所以「看它的轮盘赌怎么选情绪 → 自己写一套」和「把它的眼型参数抄成表 → 自己重调」都在合法范围内。
2. **真正咬人的是三件事：**
   - ① **直接抄代码**（含片段、常量表、素材图、字体、音效）。copy 一发生，copyleft 立刻跟上来：AGPL/GPL 都要求
     派生作品**整体**以同一许可证发布并给源码。**这跟抄多抄少无关，抄一行也算。**
   - ② **整机出货 / 打包固件的 copyleft 传染**。GPL 的义务在**分发**时触发（卖硬件、发固件、发二进制都算）；
     **AGPL 更狠：连「通过网络提供服务」也算**——所以哪怕不做硬件、只把 AGPL 代码放进联网设备或后端服务，一样触发。
     这就是为什么我们要「clean-room 重写」而不是「改一改再用」。
   - ③ **商标与署名**。[EE] 的观感借自 Anki 的 **Cozmo** 机器人（其 README 首行自陈 "as inspired by Anki Cozmo"）——
     **Cozmo/Anki 的名字与形象不能出现在我们的产品、包装、宣传里**；用 [XZ] 底座则必须在固件与关于页保留 MIT 版权声明。
3. **我们的现状**：桌面版 Sammy 是自写 Python，仓库内 grep 不到任何参考仓库的标识符/文件名，**当前零风险**。
   风险全部集中在「未来做硬件时会不会顺手抄」——所以下面列纪律。

## 四、不确定处（如实写：需要法律意见）

- **esp32-eyes 到底是 GPL-3.0 还是 AGPL-3.0**：根 `LICENSE` 与 27 个源文件头互相矛盾，法律上以哪个为准**需要法律意见**。
  我们按**严者**避让（当 AGPL 处理），反正结论都是「不能抄」。
- **desk-emoji 的「GPL-3.0 + 禁止未授权商用」**：GPL 本身不允许附加额外限制，作者这两句话在法律上如何解释**需要法律意见**。
  我们按严者避让（一律不用）。
- **「学思路」与「抄代码」的界线**：思想/表达二分法在具体实现相似度上怎么量化（clean-room 的证明标准）
  **需要法律意见**；本文件给的是保守工程口径，不是法律判断。
- **子目录未逐一核查**：[XZ] 只核到根 LICENSE、README 与已知子许可证，未对每个第三方组件（如随包的 ESP-IDF / LVGL）
  做逐条核查。真到出货前需要一次完整的许可证清单（SBOM 式）核查 + 正式法律意见。
- **出货形态未定**（DIY / 开源 / 卖硬件）：三种形态风险量级不同，**真到出货前需要一次正式法律意见**。
