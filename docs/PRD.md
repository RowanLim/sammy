> **Sammy 是一个有自己的脸、自己的声音、自己的记忆的个人 AI agent —— 住在你桌面上的小家伙。它不只是陪着你，它真能帮你把事想明白、把问题解决掉。**

## 2. 为什么要从零重做（旧项目复盘）

旧 Sammy 从 2026-03 做到 2026-08，留下 10 个顶层目录、7959 行 Python。实测结论：

### ✅ 继承的资产

| 资产 | 状态 |
|:---|:---|
| 35 个 OLED 表情（128×64 单色手绘涂鸦） | ✅ 已搬入新仓库 `assets/expressions/`，渲染层重写并验证通过 |
| 离线唤醒词（vosk，"嗨 Sammy"） | ✅ 旧项目跑通过，二期复用 |
| 硬件方案（树莓派4B + 5寸触控屏 + MG90S×2 + PCA9685，≈¥400） | ✅ 定稿，含 BOM/接线图 |
| 外壳设计（Blender v2/v3/v4） | ✅ 有模型，二期用 |
| 火山引擎（豆包）API 凭证 | ✅ 实测有效（见 §5） |

### ❌ 必须承认的问题

1. **AI 是空壳。** 半年、4 个版本，`ai_engine.py` 里 api_key 还是 `***` 占位符 —— **Sammy 不会说话**。一个"AI 伴侣"没有 AI，这是最根本的失败。
2. **零版本管理。** 7959 行代码，**一个 git 仓库都没有**。满地 `fix2.py / fix3.py / fix_demo.py / fix_web.py`，同一个功能 4 份副本，改一处不知道另三处。
3. **没有产品定义。** 没有任何一份文档说清"Sammy 到底是什么"。

### 🎯 结论

**问题不是代码，是"没有产品定义"。** 这一轮先定产品，再写代码。

## 3. 产品形态（决定 5 的解释）

**结论：先做 Mac 上的软件形态，但把它当成"实体机器人的第一块屏"来做。**

理由：
1. **实体路线有一串隐形依赖**：树莓派到手 → 装系统 → 屏幕驱动 → I2C 舵机调试 → 装外壳。任何一环卡住，进度就停。软件形态今天就能跑。
2. **现在真正没验证的是"Sammy 好不好玩"**，这件事和有没有身体无关。要是聊三天就腻，树莓派白买。
3. **树莓派不是另一个产品**，它是同一个程序的另一块屏。

具体做法（已落地在代码里）：
- 所有绘制统一在 **800×480 设备坐标系**（就是那块 5 寸屏的分辨率），最后整体按系数缩放。
- 搬到树莓派时，**把缩放系数改成 1.0 即可**，元素位置一个都不用动。
- **买硬件的时机：M2（有声音、有唤醒词）之后。** 那时体验定型，买回来直接装。

### 一期：Mac 软件形态

桌面透明浮窗（可拖拽 / 置顶 / 不挡操作）+ 表情 + 大模型对话 + 语音 + 记忆 + 双击即用。

### 二期：树莓派实体形态

同源代码，只换输出设备（屏幕 → 5 寸屏、音箱 → I2S、脸 → 舵机动作）。

### 🚫 非目标（明确不做）

- ❌ 不做通用语音助手 —— 不跟 Siri / 小爱抢活
- ❌ 不做多用户 —— 它是 Rowan 一个人的
- ❌ 不做手机 App
- ❌ 不追求"什么都能干" —— 追求"少数几件事做得有温度"

## 4. 独立大脑意味着什么（决定 1 的展开）

Sammy 不挂在 Hermes 上，所以**能力得自己攒**。这是"独立大脑"的真正代价，必须写清楚：

| 能力 | 谁提供 | 状态 |
|:---|:---|:---|
| 对话 / 给建议 / 理清问题 | 豆包大模型 | ✅ 已跑通 |
| 情绪 → 表情 | 模型输出情绪标签 + 本地映射表 | ✅ 已跑通（24 种情绪 → 35 张表情） |
| 说话声 | TTS | ⬜ M2 |
| 听懂 | 唤醒词 + STT | ⬜ M2 |
| **记得住**（你是谁、聊过什么、偏好） | 自己做（SQLite + 摘要） | ⬜ 待做 |
| **能帮你干活**（看日程、控灯、查资料） | 自己做工具调用层 | ⬜ 待做 —— **这是"解决问题"的关键** |

⚠️ 待你定：**"解决问题"要做到哪一层？** 见 §9。

## 5. 实测证据（不是设计，是跑出来的）

| 项 | 结果 |
|:---|:---|
| 大模型连通 | ✅ 豆包 `doubao-seed-2-0-lite-260215` 实测可用，回复已在人格内 |

| 延迟优化 | 该模型默认带思考链（实测多花 3.5s，`reasoning_tokens: 182`），已默认关闭；`SAMMY_THINKING=on` 可开回 |

| 表情渲染 | 35/35 张全部加载，单张渲染 <1ms（全量预热 0.03s） |
| 界面栈 | PySide6 6.11.2 + Qt 6.11.2，macOS 27 实测通过 |

**凭证管理**：旧代码里硬编码的 API key 已迁入 `.env`（权限 600，已确认被 git 忽略），**代码里不再出现凭证**。

## 6. 技术选型（决定 4）

| 层 | 选择 | 理由 |
|:---|:---|:---|
| 语言 | **Python 3.11** | 旧代码全是 Python；树莓派原生支持 |
| 界面 | **PySide6（Qt 6）** | 单进程单语言；原生支持透明无边框置顶窗口；系统托盘齐全；PyInstaller 可打包成双击即开的 `.app`。**否掉 Electron**：要额外装 Node、多一层 IPC、包体积大，而我们要的只是一个窗口 |
| 大模型 | **豆包（火山引擎）** 主力 | 凭证实测有效 |
| 语音 | edge-tts 说 + vosk 听 | 都免费、可离线，旧项目已跑通 |
| 记忆 | SQLite + 摘要 | 先跑通"记得住"，别一上来上向量库 |
| 凭证 | `.env` + 环境变量 | 永不硬编码 |

## 10. 待你拍板

1. **§4「解决问题」要做到哪一层？** 独立大脑的能力要自己攒，所以要圈定范围：
   - (A) 只会聊天给建议 —— 最省事，但"解决问题"是虚的
   - (B) 会读本地文件 / 查你 Mac 上的资料
   - (C) 会看日程、设提醒（要接 Mac 日历）
   - (D) 会控家里的灯和空调
   - 可多选。**我的建议 (C)+(D)**：(A) 太虚，(B) 有隐私面，而"日程 + 灯"最能让人感觉它真有用。
2. **记忆存哪里、存多久？** 建议本地 SQLite、不上传；默认记昵称/偏好/重要事件，可一键清空。
3. **M1 收尾要不要现在就打包成双击即开的 `.app`？** 现在跑起来要敲命令（丑但快），打包要花点时间（美但慢）。

## 11. 风险

| 风险 | 影响 | 对策 |
|:---|:---|:---|
| 又变成"改代码不改产品" | 重蹈 4 个版本各自为战的覆辙 | 本 PRD 是唯一事实来源，需求先改文档再改代码 |

| API key 泄露 | 资费损失 | 一律走环境变量，`.env` 进 `.gitignore` |
| 树莓派硬件没到位 | 二期遥遥无期 | 一期预留硬件抽象层，软件形态先独立产生价值 |
| 人格不稳定 | "AI 味"重，用几天就腻 | P0-2 单独列一条需求，专门测 |
