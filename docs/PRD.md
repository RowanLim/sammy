## 0. 一句话定义

> **Sammy 是一个有自己的脸、自己的声音、自己的记忆的个人 AI agent —— 住在你桌面上的小家伙，不是又一个聊天窗口。**

它和 Max / Nex 的区别：Max 和 Nex 是**能力**，Sammy 是**存在感**。

## 1. 为什么要从零重做（旧项目复盘）

旧 Sammy 从 2026-03 做到 2026-08，留下 10 个顶层目录、7959 行 Python。今天实测的结论：

### ✅ 值得继承的资产

| 资产 | 状态 | 说明 |
|:---|:---|:---|
| **表情系统** | 能用 | 35 个表情（含 128×64 OLED 绿屏像素脸），Web 面板实时渲染，今天实测启动成功 |
| **表情-舵机-语音联动骨架** | 半成品 | 点头/抬头/左看/右看/回中 + 组合动作（打招呼/开心/轮播） |
| **离线唤醒词** | 跑通过 | vosk 模型，"嗨 Sammy"，纯离线无需 API |
| **硬件方案** | 已定稿 | 树莓派4B + 5寸IPS触控屏 + MG90S×2 + PCA9685，预算 ≈¥400，含 BOM/接线图 |
| **外壳设计** | 有模型 | Blender v2/v3/v4 逐版迭代 + 渲染图 |
| **第三方套件资料** | 90MB | STM32 源码/PCB/原理图/固件，Sngels_wyh 开源项目 |

### ❌ 必须承认的问题

1. **AI 是空壳。** 做了半年，Sammy **不会说话** —— 对话从没接通，`ai_engine.py` 里 api_key 还是 `***` 占位符。一个"AI 伴侣"没有 AI，这是最根本的失败。
2. **零版本管理。** 7959 行代码，**一个 git 仓库都没有**。满地 `fix2.py / fix3.py / fix_demo.py / fix_web.py / update_demo_mac.py` —— 全是反复试错的化石。同一个功能有 4 份副本（tkinter 版 / Sammy_PC 版 / demo 版 / Sammybot 版），改一处不知道另三处。
3. **没有产品定义。** 4 个版本各自为战，没有任何一份文档说清"Sammy 到底是个什么东西"。
4. **技术债细节。** 目录名 `SammyDemo？` 带全角问号；同一个火山引擎 API key 明文硬编码在 2 个文件里。

### 🎯 结论

**代码不是主要问题，"没有产品定义"才是。**
所以这一轮从 PRD 开始，写代码排在第二位。**先把 Sammy 是什么想清楚，再动手。**

## 2. 目标用户与使用场景

**用户**：Rowan，一个人。

**现有环境**：
- Mac mini（主力）+ Linux 机器（上面跑着 Nex）+ iPad
- 智能家居：Yeelight / 小米 / 美的 / Cozylife，都在局域网
- 已经有两个纯软件 agent：Max（Mac）、Nex（Linux）

### 待验证的核心场景 ⚠️

> 下表是我根据旧代码和你环境推测的，**请直接在上面删改**。场景错了，后面全错。

| # | 场景 | 现在的做法 | 希望 Sammy 做的 |
|:-:|:---|:---|:---|
| 1 | **陪伴感** | 没有 | 在桌面角落待着，会累会困会偷看你，偶尔冒一句话 |

## 3. 产品形态

分两期，**形态内核保持一致：脸 + 声音 + 人格 + 记忆**。变的是"输出设备"。

### 一期：Mac 软件形态（先做，本 PRD 重点）

- **窗口形态**：桌面透明浮窗（可拖拽、置顶、不挡操作）为主，全屏模式为辅
- **脸**：重写表情渲染层，复用旧项目 35 个表情资产
- **嘴**：大模型对话（DeepSeek 主力 + 豆包备用）
- **声音**：TTS 说话 + 唤醒词
- **记忆**：记得你是谁、聊过什么、你的偏好
- **启动**：双击图标就来，不用敲命令行

### 二期：树莓派实体形态

- 树莓派 4B + 5 寸触控屏 + 双舵机，装进已设计好的 Blender 外壳
- 软件层与一期**同源代码**，只替换输出设备（屏幕、音箱、舵机）
- ⚠️ **要求：一期就要把硬件抽象层留出来**，否则二期等于重写

### 🚫 非目标（明确不做）

- ❌ 不做通用语音助手 —— 不跟 Siri / 小爱抢活
- ❌ 不做多用户 —— 它是 Rowan 一个人的
- ❌ 不做手机 App —— Mac + 树莓派够了
- ❌ 不追求"什么都能干" —— 追求"少数几件事做得有温度"

## 4. Sammy 与 Max / Nex 的关系 ⚠️ 需要你拍板

**这是整份 PRD 最关键的一个决定，它决定技术架构。**

### 方案 A：独立大脑
Sammy 自己接大模型，跟 Max/Nex 无关。
- ✅ 简单、隔离、不依赖别人
- ❌ Sammy 永远只会聊天：不能读文件、不能看日程、不能控灯、没有技能库

### 方案 B：Sammy = Hermes 的桌面化身 ⭐ 推荐
Sammy 的人格和对话由 Hermes（Max）承载，Sammy 提供"脸和声音"。
- ✅ Sammy 一出生就继承全部能力：文件、日程、智能家居、定时任务、技能库
- ✅ 旧项目其实已经摸到这个方向 —— `sammy-assistant/backend.py` 注释就写着 *"bridges web chat to Hermes"*
- ⚠️ 代价：Sammy 说话时依赖 Hermes 在运行

### 方案 C：混合
本地轻量人格保底（断网也能"嗯嗯"回应），联网时路由到 Hermes。
- ✅ 最完整、最像"有灵魂的小家伙"
- ❌ 最复杂，建议二期再上

## 5. 功能需求

> 优先级：**P0 = 一期必须**，**P1 = 一期最好有**，**P2 = 二期**。
> 每条都带**可测的验收标准** —— 做不到就不算完成。

### P0 · 一期必须

| ID | 需求 | 验收标准（可测） |
|:---|:---|:---|
| **P0-1** | 大模型对话 | 输入"今天好累"，3 秒内返回通顺中文回复；连续 10 轮不丢上下文；断网时给出友好提示而不是报错崩掉 |
| **P0-2** | 人格一致性 | 同一句话问 5 次，回答风格稳定（符合 §6 人格设定），不会一次像客服一次像哲学家 |
| **P0-3** | 表情随对话变化 | 说开心的事→笑脸，说难过的事→安慰表情；从"用户发送"到"表情切换"延迟 < 1 秒 |
| **P0-4** | 双击即用 | 双击 App 图标 → 窗口出现 → 可以对话，全程无需终端命令 |
| **P0-5** | 记忆 | 重启 Sammy 后，它仍记得你的昵称和至少 3 条关键偏好 |
| **P0-6** | 不崩 | 连续运行 8 小时不崩溃、不内存泄漏到卡死 |

### P1 · 一期最好有

| ID | 需求 | 验收标准 |
|:---|:---|:---|
| **P1-1** | 语音输出 | 文字回复的同时用 TTS 念出来，选中文本读得自然，不念表情符号 |
| **P1-2** | 唤醒词 | 喊"嗨 Sammy"（离线 vosk）→ 它"醒过来"（表情+动作响应），唤醒率 > 80% |
| **P1-3** | 空闲行为 | 无交互 5 分钟后进入发呆/打盹，随机"偷看"，不打扰你 |
| **P1-4** | 休息提醒 | 每 40 分钟主动提醒一次，带表情和动作，可一键关掉 30 分钟 |
| **P1-5** | 对话历史可查 | 能看到过去的对话记录，能清空 |

### P2 · 二期（树莓派实体）

| ID | 需求 |
|:---|:---|
| **P2-1** | 双舵机实机动作：点头/摇头/歪头，与表情同步 |
| **P2-2** | 5 寸屏全屏输出，开机自启（systemd） |
| **P2-3** | 摄像头人脸追踪：人走动时头跟着转 |
| **P2-4** | 智能家居语音控制：灯 / 空调 / 温度（对接 Yeelight、小米、美的） |
| **P2-5** | 触摸屏交互：戳脸有反应 |

| **性格** | 活泼、好奇、有点小得意；不谄媚、不油腻 | |

## 7. 技术选型（初步建议）

| 层 | 建议 | 理由 |
|:---|:---|:---|
| **语言** | Python 3.11 | 旧的 7959 行全是 Python，团队（=我们）最熟；树莓派也原生支持 |
| **界面** | 待定 ⚠️ | 选项：Electron（旧 SammyDesktop 用过，透明浮窗效果最好）/ PyQt / pygame（旧 demo）。倾向 Electron 外壳 + Python 后端 |
| **大模型** | DeepSeek 主力，豆包备用 | 你两个 key 都接触过；DeepSeek 便宜、中文好 |
| **语音** | edge-tts 念 + vosk 听 | 都是免费离线可用的，旧项目已跑通 |
| **记忆** | SQLite + 摘要 | 别一上来就上向量库，先跑通"记得住" |
| **配置** | YAML + 环境变量存 key | **不再硬编码 API key** |

## 10. 风险

| 风险 | 影响 | 对策 |
|:---|:---|:---|
| 又变成"改代码不改产品" | 重蹈 4 个版本各自为战的覆辙 | 本 PRD 是唯一事实来源，需求先改文档再改代码 |
| 外置盘被拔 | 项目不可用 | 项目在 `Mac mini/Max agent/Sammy`，建议每周 push 到远程仓库备份 |
| API key 泄露 | 资费损失 | 一律走环境变量，`.env` 进 `.gitignore` |
| 树莓派硬件没到位 | 二期遥遥无期 | 一期设计时预留硬件抽象层，软件形态先独立产生价值 |
